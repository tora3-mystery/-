# V1 村民の追加顔画像12点｜一括制作・受入仕様（2026-10-29）

対象：短編UIゲーム実験室 V1『この村の評価をお願いします。』
依頼の位置づけ：α0.6.29の既存10点に追加する顔アイコン12点。ゲーム本体は「12点揃った台帳を読んで利用、未納品なら既存画像へフォールバック」を実装済み。

## 0. 作業境界・正本

- GitHub：`tora3-mystery/short-ui-games`、最新 `main` を必ず取得。
- 編集許可：`proposals/village-review/assets/proposals/residents/` 以下に**新規素材・台帳・コンタクトシートのみ**を専用ブランチへ保存する。主担当Chatが後で取り込む。
- 禁止：`index.html`、`status.json`、`evolution-db.json`、`assets/asset-manifest.json`、ルートINDEX、他作品、既存10顔の更新。画像納品だけで公開済み／ゲーム組込済みと報告しない。
- ゲーム内の厳密な正本：`index.html` の `V1_RESIDENT_NAMES`、`v1AcceptResidentAssets`、`v1PersonId`。追加画像はこの12IDに完全一致させる。
- 参考：`assets/people/{guide,shopkeeper,farmer,fisher,inn-staff,parent,family,elderly,official,villager}.{png,webp}`。既存10点の画風・顔のサイズ感に合わせる。人物は実在人物をモデルにしない。

## 1. 必須12点（ID・人物仕様）

すべて村の住民として自然な現代日本の服装・外見。役職記号より**顔立ち・髪形・年齢・服の色の識別性**を優先し、既存10人および新規12人同士で似通いすぎないこと。性別の割当ては下記の制作上の目安（ゲーム内の発言者に固定の氏名や性別を付与する仕様ではない）。

|---|---|---|

## 2. 共通画像仕様

- **256×256px**、正方形、RGBAの透過背景。頭部～肩程度のバストアップ。背景風景・台座・フキダシ・名札・文字・ロゴなし。
- **既存10顔アイコンに合わせたイラスト画風**。リアルな人物写真、アニメ塗りへの別画風化、3D実写風への変更はしない。色温度・輪郭・照明・陰影・視線・顔位置を統一する。
- 顔の中心と大きさは揃え、外周に最低限の余白を確保。**40px程度の小表示で髪形と人物の大枠を識別できる**こと。
- 1人につき `<ID>.png` と `<ID>.webp` の2ファイルを用意する。WebPはPNGと同一の構図・透明領域で軽量化。画質優先だが目安はWebP 40KB以下。
- 透過部分を白やチェック柄として画像内に焼き込まない。服装や肌の極端な彩度を避け、施設の穏やかなジオラマ画風を壊さない。

## 3. 納品ファイル・台帳形式

保存ディレクトリ：`proposals/village-review/assets/proposals/residents/`

- PNG 12枚、WebP 12枚。
- `asset-list.json` 1点。トップレベルに `count: 12` と `files`（厳密に12レコード）。
- 比較コンタクトシート1枚：**新12人と既存10人を並べた22人比較**。既存10人は参照であり、再制作・差替えしない。元のPNG/WebPには文字を焼き込まず、コンタクトシート上にはIDを表示してよい。
- 任意で検品メモ1点。ゲームのHTMLやJavaScriptを変更しない。

`asset-list.json` の各レコードは以下のキーを必ず持つ。

```json
{
  "id": "resident-young-woman",
  "png": "resident-young-woman.png",
  "webp": "resident-young-woman.webp",
  "width": 256,
  "height": 256,
  "pngSha256": "<64文字の小文字16進ハッシュ>",
  "webpSha256": "<64文字の小文字16進ハッシュ>",
  "pngBytes": 12345,
  "webpBytes": 6789
}
```

上記の容量・ハッシュは例示値。実際のファイルを生成後に計測し、正確な値に置き換える。ファイルIDの追加・削除・改名はしない。大文字やパス付きの `png`/`webp` はゲームの受入検証で拒否される。

## 4. 既存コードとの接続・状態

- 既存10顔は `assets/people/` に存置。
- 追加顔が未納品、台帳が不完全、ID・寸法・ハッシュ書式が不正なら新顔を有効化しない（現行コードの仕様）。
- 台帳が揃ったら現行 `index.html` が `asset-list.json` を読み込み、話者の役割と文言を元に新旧顔を割り当てる。コード統合は作品Chatが担当する。
- `tests/qa_resident_voices_v0629.cjs` では模擬台帳で12IDの到達を確認済み。ただし**実画像24点の存在や画素を確認したテストではない**。

## 5. 完成条件・検品

1. 12IDすべてのPNG/WebPペアが存在し、余剰ID・重複・欠落がない。
2. 24ファイル全件が256×256、透明背景、壊れていない。PNGとWebPの人物・構図が一致する。
3. ファイルSHA-256とバイト数を台帳の実値に照合して全件一致。
4. 22人コンタクトシートで、既存10人との画風・顔サイズ・パレットの一貫性、新12人同士の識別性を原寸／40px相当で比較。
5. 特定の実在人物・版権キャラクター・既存素材の不適切な複製なし。
6. 変更ファイルは許可ディレクトリのみ。専用ブランチ、コミットSHA、納品点数、不備件数、未確認事項を明記。
7. GitHub保存、`main` への統合、Pages配信、320/390px実ブラウザ操作、最終人間レビューは**別の工程**として報告する。

## 6. 制作後の引き継ぎ

Workが専用ブランチへ保存 → 作品Chatが最新mainとの競合を確認して受入・必要時に統合 → 回帰テストと公開画像読込チェック → 人間がα版の村民発言・顔のバリエーションを確認。重要なバランスやエンディング条件はこの画像制作では変更しない。
