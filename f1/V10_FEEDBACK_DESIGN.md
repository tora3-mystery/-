# F1 v0.10 RC｜初見プレイフィードバックへの対応と契約ルート再設計
更新：2026-10-25 JST／**作業ブランチのみ、main・GitHub Pages未反映**

## ユーザーの4要望と対応

1. 対応済みのクレームをグレーアウト：`.complaint-ticket.resolved`で背景・枠色・色味を抑える。開いた苦情は従来の白色・優先表示を維持。
2. 未解決／未対応には店長コメント不要：カード上の翌日返信予定プレースホルダーと未解決投稿の返答表示を廃止。解決済みになった時点で対応完了報告を付与し、その投稿のみで読める。顧客の声が消えるわけではない。
3. 苦情パラメータの符号を明確化：集客力は増加が有利、苦情は減少が有利と一覧下に常時表示。施策カードでは「－n件（改善）」「＋n件（悪化）」と記載。数式と既存経営ルールは不変。
4. 0番レジの不穏ルートが分かりづらい：「よく分からない帳簿処理」から**禁じられた売上保証の儀式＝危険な契約**に変更。選ぶ前に得られる集客と人的代償を明示。エンディングの条件、土曜6同一、日曜の仮正常化、人曜日、未来の自分／昨日の真相を残す。

## 危険な契約の因果

- 水曜（最短）：`audit`｜**禁じられた「売上保証の儀式」を試す**。集客力＋2（即日）。閉店後に帰れない人＋1。店長本人が分からないまま黒い契約書に署名する。
- 木曜（最短）：`camera0`｜**契約書に客の名前を書き足す**。集客力＋1、帰れない人＋3。売上は伸びるが、帰宅者の名簿が欠け始める。
- 金曜（最短）：`open0`｜**0番レジで契約を完成させる**。集客力＋1、帰れない人＋5。0番レジが契約執行装置と分かる。契約の責任が店長自身にも移る。
- 土曜：契約MAXの場合、6択がすべて「契約に従い閉店を申請する」になる。契約した代償として意思決定権が消える。
- 日曜：一見正常に戻る。閉店後、契約の請求書が届く。怪異の選択は「今後の利益を捨てて契約を破棄」「代償を受け入れ契約を継続」「契約者と代償を推理」。
- 人曜日：契約を続けたことで現れる8日目。店長は通常の経営施策を選べず、契約の履行・拒否だけが残る。
- 隠しエンド：証拠A（契約者から営業日を徴収）、B（未来の店長の映像）、C（返却希望は一営業日）を照合し、「未来の自分」「昨日」に到達。0番レジの本来の役割が分かる。

**経営式は変更なし**：日売上＝max(0,30＋10×集客力－10×未解決クレーム)。禁忌施策の集客力アップも通常式に含まれるので、危険だが利益があるという選択理由が成立する。利用すると1日1施策の枠を消費し、苦情の処理機会も失う。
