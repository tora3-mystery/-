# F1「改善しすぎる店」｜売上一本化・日数コスト案（設計検証中）
策定：2026-10-25 JST／状態：**未実装の企画提案。ユーザーの方向性を踏まえた仮想5視点レビューであり、確定仕様ではない。**
対象：通常経営。現行 f1/index.html の旧資金モデルは**変更しない**。実験はモデル単体の計算だけ。main・ルート index.html・d3/・m2/ 等は改変禁止。画像生成・Work着手も禁止。

## 1. ユーザー意向と採用すべき核
- 7日間、1日1つの施策、初日に異なる5件の未解決クレーム、翌日に店長返信。複数件の未解決クレームの件数と内容が選択に応じて変化。
- 資金残高、改善費の金額、仕入／人件費／原価率は撤廃。**唯一の経営目的は、客が離れないよう売上を維持すること**。
- 平常時売上100万円/日を基準とし、未解決クレーム1件ごとに基準売上-10万円。未解決10件なら売上0万円、ゲームオーバー。
- 改善施策の負担は金額でなく**着手から効果が出るまでの営業日数**。7日間の7回の決断は維持し、工事は進行中でも別の短期施策を選べる。
- クレームが増えても本部は計測方法・施策実施率の変更で「改善率100%」と評価できる。店長は個々の苦情に翌日返信する。
- 既に合意された怪異の物語・3日目からの怪しい施策・土曜6同一・日曜復帰・人曜日・X1〜X4の筋書きは維持する。

## 2. 基本式（確定候補）
- `C_d`＝その日、開店時に未解決のクレーム件数。
- **基本売上** `B_d = max(0, 100 - 10*C_d)`［万円/日］。
- `C_d >= 10` の朝に売上0万円となったら、通常ルートは即ゲームオーバー。商品券や販促額で機械的に復活しない。最終日7日目に対策実行後も、翌日の閉店見込みが0なら週末評価で「継続不能」とする案。
- **販促**を入れる場合のみ `R_d = B_d + P_d` （`C_d < 10`のとき、Pは例えば当日+10〜20万円、クレーム追加が翌日発生）。商品価格の詳細な計算は導入しない。0のゲームオーバー判定を販促増額で免れることは不可。
- クレームが0なら基本売上100万円。累計売上は7日間のRを足すだけ。設備費や負債管理なし。
- UIは「今日の売上見込／未解決のクレーム／今週の累計売上」を中心に。苦情は個別投稿と種類・投稿者を表示。4不満度の内部表現は必要ならロジック補助で残し、プレイヤーの画面には別の4本の経営ゲージを強制しない。

## 3. 毎日の時間順（混乱を避けるため一義化）
1. 朝：前日から持ち越した工事が完了したらクレーム件数・内容を変更。前日の店長回答を公開。
2. 朝：現時点の未解決件数`C_d`を確定し、売上見込`B_d`を表示。10件以上ならここで0万円・ゲームオーバー。
3. 営業中：6候補から1施策を選択。即効策なら当日末に、工期2日なら翌日末以降など、選択肢ごとの予定日に施策効果が出る。
4. 閉店時：当日売上`R_d`を計上。販促の当日限定上乗せを加算。施策の副作用で発生する投稿は**翌日**見せる。個々の店長回答も翌日に公開。
5. 最終日：7日分の累計売上／週末の未解決件数／実際に選んだ施策／本部の改善実施率を表示。閉店時に発生した翌営業日への悪影響も判定から抜け落ちないよう週末見込みに加味。

**日数の定義**：`即日`＝選択日の閉店時に効果が出て翌日の売上から反映。 `工期2日`＝選択日＋翌日まで作業、翌々日の朝から効果（例：月曜選択→水曜開店に反映）。 `工期3日`＝木曜開店に反映。選択日・完成日を明示し、日数の別解釈を防ぐ。

## 4. 施策の役割（例、効果はバランス調整前）
| 施策の役割 | 日数 | メリット | デメリット／ブラックユーモア |
|---|---|---|---|
| レジ誘導員を配置 | 即日 | 翌日のレジ苦情-1 | 案内放送・誘導がうるさいという新規投稿を誘発し得る |
| シフトを最適化 | 工期2日 | 完成後にレジ苦情-2 | 今日のレジ苦情は残り、客の忍耐が続かない |
| セルフレジ導入 | 工期3日 | 完成後レジ苦情-3 | 操作しにくい／サポート呼び出しの苦情+1 |
| 棚を小型化 | 即日 | 通路苦情-2 | 欠品クレーム+1。「乳製品が見つからない」 |
| 臨時補充 | 即日 | 品切れ苦情-2 | 搬入がうるさい→騒音苦情+1 |
| ポイント5倍セール | 即日 | 当日の売上+20万円（例） | 次の日に行列・品切れの投稿が2件増える |
| レジ待ちの計測位置を変える | 即日 | 本部の待ち時間KPIは80%改善 | **現実の苦情-0／基本売上は減ったまま** |
| 怪しい「未処理売上の自動照合」 | 既存怪異仕様に従う | 帳簿上の売上が増加 | 実売上とは違う。日付がずれ、客の人数が合わなくなる |

日数だけが負担で、工期の長い施策でも複数回の決断を奪う方式は避ける。期間内に効果が出ない施策は候補に出さない。経営体験を難しくするために仕入やスタッフ疲労など別ゲージは追加しない。

## 5. 仮想5視点の批判的レビュー
### ゲームデザイナー
クレーム減少が売上増加に直結する仕組みは明快。しかしこの式だけなら「一番たくさんクレームを減らす即効施策」を選ぶだけになる。販促の当日売上と将来の苦情、および長期施策の後日の便益を競わせることが必須。
### 経営シミュレーション担当
手持ち資金の計算を廃止すればUIも説明文も大幅削減。代わりに、見込み売上と累計売上を別に表示し、ゼロになるタイミングを明示。販促で今日の売上が増えても、明日から減るトレードオフにする。週間目標は仮に450万円以上、ただし多数戦略の再試算で決める。
### シナリオ担当
初日5件に対する店長翌日回答と、同じ客が異なる苦情で戻る仕組みを残す。「複数の苦情を移動させただけ」なのに本部が毎日褒める。0円になると開店中止の張り紙が出るような、日常的で乾いた結末が似合う。
### UX担当
日数は「0日・2日・3日」の曖昧表記より「即日／水曜完了予定」など完成日を併記する。毎日6択を維持し、「本日売上見込」「明日以降のクレーム増減（目安）」「進行中1件」を表示。長い情報一覧は折りたたむ。
### QA担当
0円ゲームオーバーが早すぎる／遅すぎる、日曜の販促副作用を週末判定から逃す、怪異MAXの土曜同一6択で急に倒産、工事完成の前後、保存再開と7エンディング、新ルールへの旧v0.8データ移行を重点検証。

## 6. 簡易シミュレーション（本番実装ではない）
旧ゲームにある29種類の**通常施策の4不満度delta**、既存の苦情件数への換算を使い、資金コストを外して日別売上に置換する概念試験。販促増分は旧bonusの60%、売上確定は施策前の朝、10件以上で0円とした。各戦略を600本の試行で評価。リプレイ入力が同一なら決定論的に同じ結果であり、人間の勝率ではない。
- `-10万円/件`案で無作為な通常施策選択：600試行中ゲームオーバー2件／累計売上平均約419万円。
- 苦情減少を最優先する固定選択：ゲームオーバー0件／累計約590万円。
- 販促の額を最優先する固定選択：5日目で売上0円（繰返し戦略なので600試行とも同じ経路）／累計215万円。
**解釈**：開始5件→10件ゲームオーバーという閾値は説明しやすいが、旧施策を流用するだけでは苦情削減戦略が圧倒的に強い。工期・販促・苦情の分散先を新モデル前提で再調整する必要がある。

## 7. エンディングとの整合（未決・最終試験で決める）
- `normal_success`（N1）：週の売上目標を達成し、最終日も未解決件数が小さい「選ばれる店」。現行名「優良店舗」を維持可能。
- `normal_customer`（N2）：売上目標は達成したが、多くの未解決苦情が残る「売れたのに嫌われる店」。旧「黒字の不便な店」は資金モデルの廃止に合わせ表示名を変更する方が自然。
- `normal_strain`（N3）：目標未達または売上0円で営業終了。「改善しすぎた店」は内容に合うか再検討。
- 怪異X1〜X4の**ストーリーと曜日演出は現行仕様を維持**。ただし「異常利益を現金から返還」の数値表示は廃止し、帳簿上の「異常計上売上」を訂正する形式に置換が必要。帳簿だけ繁盛しても現実の顧客が消えるという対比を活かす。現時点でコードは未変更。
- 通常N1は怪しい施策を1件も選ばず到達できること、怪異MAXは日曜・人曜日まで到達できることを、独立の決定論的な到達経路で保証する。
