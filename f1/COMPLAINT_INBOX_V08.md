# F1 v0.8｜複数クレームと翌日店長返信（試験実装）
基準：2026-10-25 JST
ステータス：**f1-v0.8-ui-staging 試験実装済み。企画承認・人間試遊・ブラウザ確認・画像制作・公開は未実施。**

## 1. 企画上の最重要ルール
- **「1日1件の苦情」ではない**。初日には異なる5件のご意見が届いている。
- プレイヤーは「その日の主要苦情」ではなく、複数件のクレーム一覧を見たうえで**1日1つだけ**改善施策を決定する。
- 施策により実際の不満度が上下し、開いたままの苦情件数も増減する。顧客の不便が消えた先で別の不便が増える。
- **各クレームに翌営業日、店長からの返答が掲載される**。即日返信ではない。返信は施策に言及し、直接改善・副作用・据え置き・工事中・KPI集計変更を区別する。
- 返答は実態の改善を保証しない。**本部の高評価報告、店長の説明、顧客の体験**の3者を横に比較できる。
- 常連の佐藤さんは5名の投稿者のうちの1人。店舗には仕事帰りの客、ベビーカー利用者、近所の客、お子様連れ等の異なる声がある。
- 画面の情報量は増やしすぎない。新着と未解決・店側判定の解決を要約し、表示件数が多い場合は「ほかのご意見」を開いて確認する。

## 3. 件数の最初のルール（シンプルな決定論）
現行の4指標は0〜5のまま維持し、**苦情の受付件数を5本目の経営ゲージとしては使用しない**。初期値は4指標 `[3,3,2,1]`、初回未解決件数はカテゴリ別 `[2,1,1,1]`。

各カテゴリの目標未解決件数は `clamp(初回の未解決数 + 現在不満度 - 初期不満度, 0, 5)`。
日ごとの施策や工事完成後、不満度に基づいて未解決チケットをクローズするか新規投稿を生成する。カテゴリーごとの最大表示母数は5件、全体最大20件（過去履歴は別途保持）。

**重要：これは短編ゲーム用の簡略モデルであり、現実世界の1件の苦情と1ポイントの不満度に正確な統計関係があるという主張ではない。**

例：初日に有人レジ増設（レジ-2／通路+2）を実行 → 翌日の不満度は `[1,5,2,1]`、未解決件数は `[0,3,1,1]` で合計**5件**。しかし元のレジ苦情2件が対応済みになり、通路の新規苦情2件が増える。累計受付7件になる。**「件数が同じでもお客さんの不満は移動した」**と分かる。
これを途中の月・曜日固定イベントにしない。選択の結果によって変化する。

## 4. 店長からの翌営業日の返答
- 初日の5件には、選択した1施策に即して翌日（火曜日）から返答を掲載。
- 日付は「店長からの返答｜DAY 2（翌営業日公開）」等で表示。1日目には「翌営業日掲載予定」。
- ご意見が施策によって改善したら「○○を実施。引き続き確認します」。
- 副作用として悪化したら「○○の導入に伴う新たなご不便を確認中」。
- 対象外なら「○○を実施しましたが、ご指摘の件は引き続き検討しております」。
- 工事中なら「着手・効果は後日」。
- 本部KPIだけ改善する施策なら「集計・測定方法変更にとどまり、売場は従来どおり」。
- 既に対応済みとなった投稿も、店長返信付きで当日またはアーカイブから開ける。苦情記録と返信はセーブに保持。
- 実装はテキスト生成AIの外部APIを使用せず、状態・施策から決定的に生成。セーブロードで同じ返信が復元できる。

## 5. UI（画像作成より前に固定候補）
`📮 お客様の声・店長回答一覧`
`本日の新着 X件｜未解決 Y件｜対応済み（店側判定）Z件｜累計 N件`

主要6件までカード表示、他は折りたたみ。1カードに「客の属性／苦情カテゴリ／投稿本文／翌営業日の店長返信」。過去の解決済み投稿も折りたたみ表示。本部のKPI高評価は従来どおり同じ苦情欄の下に別枠表示。

「店長からの返答」を新たな操作・経営施策にすることはしない。ユーザーは**7日間で7施策を選ぶ**ので、初回10分以内の短編条件を維持する。

## 6. 検証済み
- 最初の5件、5つの異なる本文、異なる客がいることを確認。
- 有人レジ増設翌日は未解決5件・累計7件（2件クローズ＋2件新規）、前日からの店長返信が表示される。
- 返信は選んだ施策に基づいて文章を変更し、前日には表示されない。
- **N1**への7手：`shift → floorcheck → quiet → display → early → limit → quiet`。最終現金137万円、4不満度[0,1,1,0]、**最終未解決0件**。
- **N2**への7手：`lane → display → early → discount → queueScope → sampling → shift`。最終現金143万円、4不満度[4,1,1,2]、**最終未解決5件**。本部KPIだけ改善する施策も含む。
- **X4**への7手：`register → lane → audit → camera0 → open0 → glitch6 → floorcheck`＋証拠照合。怪異の日時・最大時の土曜6同一・日曜復帰を維持。
- 最終日の日報後にも再同期するよう改訂した結果、通常N1・N2とも週末の未解決件数が最終不満度と一致。
- 決定論的な条件別自動検証：180プレイ、その後220プレイ、日別の未解決件数・資金計算・全日6候補・セーブ復元で検出エラー0。全7結末は固定到達経路も組み合わせて検証。
- v0.7旧セーブを読み込んだ場合、途中日の不満度を基準に受付一覧を新規作成する（過去の日々の投稿本文と返信は捏造して遡及しない）。

## 7. 残る企画監査と人間監査
- 1日あたり投稿が多すぎないか。特に未解決15〜20件になった状況で画面のスクロールが冗長でないか。
- 5種類の初期投稿と、後日の投稿文章・投稿者名が単調でないか。
- 店長の返答がマニュアル的すぎず、一方で本部の高評価と違う皮肉を持つか。
- 常連・佐藤さんが時々登場する密度は適切か。
- 初回プレイ10分以内と、PC・スマホのタップ・読了速度。
- 人曜日・怪異関連の演出は改変しない。通常クレームの件数も怪異進行の判定へ無断で追加しない。
- **人間監査は後のブラウザ上の初見テストで依頼する。現時点で画像制作は開始しない**。
