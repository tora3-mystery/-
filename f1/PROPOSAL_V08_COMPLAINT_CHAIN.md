# F1 v0.8｜通常経営・クレーム連鎖再設計案（未合意）
更新基準：2026-10-24 JST。**これは企画審査用の提案であり、実装合意・画面確認済みではない。**
対象：`f1/` 配下のみ。既存の画像21枚契約もこの企画確定後に再評価。画像制作・Work依頼・main公開はまだ行わない。

## 企画コンセプト
**「クレームを解決した結果、別のクレームが生まれる。そして、その因果を当事者として引き受ける7日間」。**
プレイヤーは7営業日で1日1施策、原則6案から1案を選ぶ。利益と4つの不満度（レジ待ち／通路／品切れ／騒音）を管理する。新しいメーターを増やすのではなく、数値変化を具体的な顧客の言葉と結びつける。通常営業だけでも一つの短編ゲームとして成立し、怪異ルートの介入は任意。

## 実装方式の比較
- A 文言差し替えのみ：安いが選択による原因認識が一過性。補足程度。
- **B 原因付きクレーム＋既存4指標＋選択候補の妥当性保証（推奨）**：施策により「誰が何に困ったか」が翌日発生し、クレーム対策が次の問題を誘発する。10分以内を維持しやすい。
- C 新たな顧客層・スタッフ疲労・在庫などのサブメーター追加：深くなるが短編の理解負担とテスト対象が増える。現段階では不採用。

## 1. 7営業日の構造（固定の問題発生は禁止）
| 営業日 | 機能 | 変化の条件 |
|---|---|---|
| 1 | 共通導入、レジと通路が困っている | 初期値 [3,3,2,1]。チュートリアルと初回施策を提示 |
| 2 | 最初の副作用 | 1日目の選択と工事の完成条件からクレームを出す |
| 3〜4 | 第一の改善連鎖 | 新しく顕在化した不満、継続中の不満、利益機会を競合させる |
| 5〜6 | 不満と収支の相克 | 無料施策の効果逓減・先行投資の回収・問題の再燃を可視化 |
| 7 | 最後の判断 | 過去の施策が残した課題を提示し、1施策で締める。選択後に通常3分岐判定 |

3日目に必ず品切れ、5日目に必ず騒音という現行固定イベントは廃止。イベント時刻ではなく原因施策・数値の閾値・工事完了で発生する。プレイヤーが正しく対応したのに唐突な苦情が増えることを避ける。

## 2. 新しいクレームの発生源（コアの12例）
| 発生した施策／状態 | 反映する既存効果 | 次に届く顧客の声（案） |
|---|---|---|
| 有人レジを増設 | レジ-2、通路+2 | 「レジは増えました。でもベビーカーが通れる幅まで減っています」 |
| セルフレジ導入（完成後） | レジ-2、通路+1、騒音+1 | 「会計は早いけど、操作の説明を聞くために並んでいます」 |
| 通路を一方通行 | 通路-2、レジ+1 | 「通路は空いたのに、レジに行くまで店を一周しました」 |
| 陳列棚を小型化 | 通路-1、品切れ+1 | 「歩きやすくなりました。いつもの牛乳はどこへ行きました？」 |
| カート動線を変更 | 通路-1、レジ+1 | 「買い物はスムーズ。最後だけ人が詰まっています」 |
| 臨時の追加発注 | 品切れ-2、騒音+1 | 「商品が戻ったと思ったら、品出しの声掛けがずっと響きます」 |
| 購入数量を制限 | 品切れ-1、騒音+1 | 「『一人2点まで』の説明がレジで10分続いています」 |
| 試食祭り | 品切れ-1、レジ+1、通路+1、騒音+1 | 「試食は楽しいです。買う人と通る人の行列が全部一つになっています」 |
| ポイント5倍セール | 売上増、レジ+1、騒音+1 | 「得したい人が集まりすぎて、買い物が終わりません」 |
| 見切り販売 | 売上増、品切れ-1、レジ+1 | 「値引きの時間だけ、レジ待ちが二倍になりそうです」 |
| 放送縮小 | 騒音-2、当日売上-4万円 | 「静かで助かります。特売を知らずに帰った人もいるみたいです」 |
| 早閉め | 売上-14万円、レジ-1、騒音-1 | 「従業員は早く帰れます。でも仕事帰りのお客さんは間に合いません」 |

上表は**原因別に差し込む文面案**。既存の数値効果と不一致な新しい苦情値を無断で加算しない。効果のないレジ待ち不満を、文章だけで発生したように描かない。放送縮小・早閉めなど金銭面の副作用は「営業報告／ご意見」へ配置する。

## 3. クレーム判定（数字とストーリーを一致させる）
保存する原因イベント（案）：
`{actionId, originDay, affectedMetric, delta, active, narrativeId}`
ただし、保存量と互換性を小さくするため、可能なら `s.days` と `s.last` から再構成し、必要最小限の属性だけ追加する。

翌営業日の見せ方：
1. 前日に発生した副作用の該当指標が3以上→新クレームとして最優先。ただし他の未解決指標5を見えなくしない。
2. 上記がない場合、不満度4以上の継続課題→再問い合わせ／再燃。
3. すべて3以下なら前日の施策の効果と小さな不満を表示。
4. 全項目2以下なら具体的な感謝の声や店員報告。毎日必ず大問題を起こさない。
5. 複数同時の場合、メイン1件＋「ほかの気になる声（最大2件）」だけ。展開と原因が見えなくなるほど長文を積まない。

画面に表示する文章は「顧客の声（具体的な体験）」＋「原因タグ（直近の施策名）」＋「現在の不満度」。説明は後追いで確認でき、当初から正解や正しい施策を明示しない。
「新着の声」「継続中の声」「改善への感謝」を異なるラベルで区別する。

日報で選択直後に見せるもの：
- 手元資金の増減、売上・仕入・人件費・維持費・改善費
- 不満度4項目の変化（例：レジ待ち -2 / 通路 +2）
- 「改善したこと」と「生じた副作用」各1行
- 工事の場合：先行投資と翌日完成予定。まだ効果が発生していないことを明示
- 次の日に現れる苦情の正体は日報で断定しすぎない（翌日にクレームを受け取る面白さを残す）

## 4. 6選択肢の品質ルール
カテゴリ固定ではなく現状に応じた「役割」を保証する：
- 現在の主課題に有効な即効策（適切なものがある場合）
- 主課題に有効だがコスト・遅延・別の副作用が異なる代替案
- 無料または低コストの応急策
- 利益・集客を優先する策（苦情への副作用あり）
- 中期投資か、別の問題への対応
- 状況に応じた探索的・監査的な施策（不穏ルート入り口も一般の業務施策として自然に混ぜる）

必ずしも全日で6役が独立して埋まるわけではない。候補が6未満になる場合は妥当な反復候補で補充し、無限ループを防止。資金不足でも実行可能な選択肢を最低2つ用意する。
深刻なクレームに直接有効な対策が画面から突然消え、理由も示されない状況を防止する。
前日施策の副作用を根拠に「なぜ今日この案があるか」を小さく説明する。**不穏施策のみ別色にしない。**

## 5. 連鎖のデザイン例（固定一本道ではない）
レジ混雑 → 有人レジ増設 → 通路悪化 → 陳列棚小型化 → 品切れ → 追加発注 → 店内騒音 → 放送削減 → 売上減 → 見切り販売 → レジ混雑。
これはゲームの因果連鎖を説明する**可能な一本の例**であり、固定的に必ず起こる7日イベントでも、現在の6候補メニューで全手が毎日選べることを保証したものでもない。
施策の代替経路：
- レジは有人増設／セルフレジ／シフト組換／整理券
- 通路は一方通行／棚小型化／カート動線変更
- 品切れは追加発注／発注システム／購入数制限
- 騒音は放送減／BGM停止／振動呼出
異なる施策の連鎖が別の人間的な苦情を引き起こす。最終的な達成条件はN1（現金120以上＋深刻な不満なし）、N2（現金120以上＋深刻な不満あり）、N3（現金120未満）を維持。

## 6. 不穏ルートとの接点
通常の因果連鎖を作り込んだ後、異常度は「合理的だが履歴が不透明な業務施策」から進める。
怪異で通常経営のルールを強制的にねじ曲げない。通常施策を選び続けた人にホラー演出が無条件で発生してはいけない。
レシート・監視映像・閉店後取引の謎、X1〜X4は既存の改訂案を尊重。ただし、選択前に「怪しいルート」を示す見た目、日数固定の怪異強制イベントは不採用。
不穏ルートの詳細な分岐・伏線・8日目・推理UIは通常経営確定後に別途審査し、この提案に混ぜて早期凍結しない。

## 7. QA受け入れ条件（実装前に合意）
1. 7営業日の各日、正常系4指標の状態と原因が食い違わない。
2. 主な施策12種について、予期される当日・翌日影響とクレーム文面が一致。
3. 固定3日目／5日目クレームはなく、直前の行動による違いが2日目以降の本文に現れる。
4. 日報と翌日のクレームの時間関係が明確。
5. 6候補、強制ホラーなし、負資金・工事・繰返し・戻る操作・セーブ再開で詰まらない。
6. 特定の無料施策ループだけが毎回N1になる偏りや、高額投資が必ずN3になる不合理を避ける。
7. 全7エンディングに到達できること。特にN2とX2の取得条件を再現可能な施策列で検証。
8. 初回プレイ10分以内、PC・320px・390px・タブレットで読みやすい表示。人間の初見テストは別途。
9. 画像枚数と切替条件は、この通常経営案および後続の怪異設計を確定してから最終決定。
10. `index.html`、`d3/`、`m2/`、共有設定は編集禁止。

## 8. 企画レビューの3段階
- ゲームデザイン監査：毎日何に悩み、何が学習され、どの判断が回収されるか。
