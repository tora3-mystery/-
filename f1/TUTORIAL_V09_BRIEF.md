# F1 v0.9｜M2型プロローグ・操作チュートリアル追加指示

作成：2026-10-25 JST  
状態：**2026-10-25 13:01 JSTにF1ゲーム本体へ統合し、モデル・DOM・実ブラウザQAを完了。一般公開は未実施。**

## 1. ユーザー要望と狙い

「いきなりページに入るんじゃなくて、設定とかを教えるチュートリアルページがほしい。操作説明とか。M2がそこら辺とても良い」。

M2 `m2/index.html`（main、α0.6.1）の導入画面は「前日の状況→今朝の事故→主人公の立場→達成すべき仕事→関係者→開閉式の操作説明→明確な業務開始ボタン」という構成。F1はゲーム開始前に`#intro`こそあるが、説明が短く、数式が先行する。また保存データがある場合、ページ再訪時に`load()`からゲームを直接再開するため、説明画面を見られないことがある。

**解決方針：M2の情報設計を参考にして、F1固有の世界観でプロローグを再構成する。既存M2の素材やコードは変更・コピーしない。**

## 2. 画面の完成イメージ

- 入口は独立したプロローグ画面。店内ゲームUI・6択施策・日報は「営業開始」を押すまで出さない。
- 開始前に状況が把握できる**本部からの引継ぎ通知**の体裁。F1らしく、普通の業務連絡の中にひとつだけブラックユーモアを混ぜる。
- 見出し：`改善しすぎる店`、ラベル：`月曜日 08:45｜店舗運営本部`。
- 画面はスマホで読みやすく、長すぎない。ストーリー・使命・操作の三段構成。詳しい説明は開閉式。
- スタートは`7日間の店長代理を始める`。タイマーなし。開始前に時間が進まない。
- 初回の操作説明には怪異、0番レジ、曜日異常、人曜日などの情報を**絶対に出さない**。日常の経営判断として遊び始めさせる。

## 3. プロローグ本文案

> **店舗運営本部からのお知らせ**  
> 件名：【業務連絡】店長代理の任命について
>
> まるまるスーパーでは、最近「お客様の声」が増えています。レジの行列を解消すると通路が狭くなり、品切れを減らすと売場が騒がしくなる。改善の報告は毎日届くのに、苦情だけがなくなりません。
>
> 店長が一週間不在となるため、本日から7営業日の店舗運営をあなたに任せます。
>
> 本部からの指示は簡単です。**売上を維持し、お客様の声に対応してください。**
>
> ※本部は改善施策の実施状況を評価します。売場の状況とは別集計です。

初日の店の状態はカードまたは3指標で簡潔に可視化：

- 集客力 `7/10` — 来店したい理由
- 未解決クレーム `5件` — レジ・通路・品切れ・騒音に関する声
- 日売上見込み `50万円` — 現状のまま営業した場合

## 4. 仕事は2つだけ

**① 毎日、お客様の声を確認する。** 5件の初期投稿を読んで、いまの店で何が起きているか理解する。

**② 毎日6案から1つ、改善策を選ぶ。** 「集客力」「苦情件数」「効果が出る日」が変わる。すぐには解決しない施策もある。

これを7営業日繰り返し、店舗を存続させる。

## 5. 操作ガイド（初期表示は閉じた<details>）

見出し：`操作ガイドを見る（営業はまだ始まりません）`

1. **お客様の声**：各投稿を開き、内容と日付を確認。店長からの返信は翌営業日以降に表示。
2. **施策を選ぶ**：毎日6案から1つだけ選択。施策カードの「当日の集客力」「反映日」「苦情の増減」を読む。
3. **営業日報**：選択後に当日売上・未解決件数・本部速報を確認。「翌営業日へ」で次の日へ。
4. **進行中の施策**：工事・制度変更は翌日以降に効果が出る。完成前でも別の施策を選べる。
5. **売上の考え方**：`日売上（万円）＝max(0,30＋集客力×10－未解決クレーム×10)`。苦情を減らしても集客力が下がれば売上は落ちる。
6. **失敗条件**：売上0万円で閉店、日売上40万円未満が2営業日続くと店長交代。初回低迷日には警告する。
7. **保存**：この端末・ブラウザに進行状況を自動保存。ネット接続やログイン不要。

ここまで初期画面に全部を表示しないこと。数式と失敗条件は`基本ルール`として短い要約を置き、細部は開閉式にする。

## 6. 初回と再訪時の導線（重要）

- **新規訪問**：必ずプロローグを表示。ゲームの盤面に直行しない。
- **保存済みで再訪**：盤面をいきなり表示せず、プロローグ上に `続きから再開（DAY XX）` と `最初から始める` の2導線を設ける。
- **「続きから再開」**：保存された状態に戻る。日報で止まっていた場合は日報のまま復帰し、クリックなしで翌日へ進めない。
- **「最初から始める」**：既存の記録を消す前に確認ダイアログを出す。無断で上書きしない。
- **説明を見直す**：営業中のUIに`遊び方・業務指示を確認`リンクを設置。保存内容や日付を変更せずにプロローグ説明を再表示し、`営業に戻る`で元の状況に復帰。
- 既存`#intro` / `#start` / `restart()` / `load()` / `persist()`を踏まえ、保存キー `f1-v09` を維持。既存の自動テストは壊さない。必要ならテストの開始操作を明示的に更新する。

## 7. QA受入条件

- 320px・390px・PCでプロローグの表示／ボタン／折りたたみが破綻しない。
- 初回は説明の後に`営業を始める`を押すまで、ゲームの6択を表示しない。
- 新規開始で初日：集客力7／クレーム5件／売上見込み50万円。
- 1日進行→保存→再読込→再開で次の日に飛ばない。日報途中のリロードも正しく復帰する。
- 説明再表示中はゲームの進行・売上に影響なし。
- 通常N1/N2/N3、早期閉店、店長交代、不穏X1〜X4へのルートに影響なし。
- 企画監査：冒頭で「店長代理になった理由」「7日間の仕事」「1日にできること」が理解できる。
- **作業は`f1/`内だけ**。Workが編集中なら、最新HEADと差分を確認してからF1 HTMLを修正。ルート`index.html`・M2・他ゲームは変更しない。
