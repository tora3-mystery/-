# F1 店舗写真・状態遷移の再設計｜v0.18素材仕様案

策定日：2026-10-27／制作前監査改訂。同一スーパー写真34ファイルは**上限候補であり、必要枚数は代表画像検品後に最終確定**。画像は未制作・未反映。公開中の本体はv0.17.3。

## 目的と実装担当

ユーザーレビュー：「大きなスーパーの画像の変化が分かりにくい。大きな写真は数十状態を用意し、下のアイコン的な状態表示は維持してよい」。既存16点のv0.16追加画像は欠陥ではないが、主題の売場や撮影角度が場面ごとに変わるため、店舗全体の「昨日→今日」を比較しづらい。直近の施策で写真を選んだ後、深刻な苦情で別写真に上書きするコードもあり、主画像が店全体の最終状態を表せていない。

- **Chat**：以下の選択ルール・仕様を策定。ゲームコードへの組込みとバランスQAを担当。
- **Work**：代表3枚で同一店舗・同一カメラアングルの統一を検証した後、承認された素材34点を製作、WebP圧縮、検品、台帳保存、GitHub `f1/assets/` 内へ反映。原則 `f1/index.html` を変更しない。
- 既存の`scene-*.webp`16点は残す。グレー施策、オーナー視察、社、DAY 8などの近景・結果演出には再利用できる。通常経営画面の主写真のみ新系列へ切替予定。

## 固定カメラ・画作り

- ワイド16:9、公開時1100×619 WebP（品質80～84を想定）。比率、カメラ高さ、視野角、主な什器座標、照明色、店名を**原則全状態で一致**させる。機器増設・大規模改装による意図的な什器差分は専用の設備履歴として扱い、通常場面へ無断で戻さない。
- カメラ：入口横の通路から店内を斜めに眺める、少し高い固定地点。**画面左に白いレジ3列、中央に買い物カートが通る主通路、右に日用品・食品棚、奥に店内放送設備**が一画面に収まる。
- まるまるスーパーの世界観は実在チェーンのコピーをせず、既存マスター画像のオリーブ色の柱・ベージュ床・緑のカゴ・白いレジ・暖色寄り照明を固定。
- 状態変化は「人の数・列の長さ」「障害物とカート動線」「棚の空き」「放送現場の様子」に限定して明確化。変化前後で**同じ床・壁・レジの位置**が保持されることが最優先。
- 音は写真自体で表しづらいので、スピーカー付近での大きな身振りや客の反応を使う。音量の正確な数値は下のゲーム内表示で補う。
- 写真内の文字・会社ロゴ・商標は読めないか架空。人物は架空。過度なAI的発光、ピクセル・枠線、説明文字の焼き込みを禁止。

## 主写真選択の決定ルール（実装前の承認案）

1. **DAY 8／DAY 7の通常復帰／社の段階**は専用の既存演出を優先。隠しルートのメタ説明やネタバレラベルは表示しない。
2. 通常の日は、4種の苦情 `vals=[queue,aisle,stock,noise]` と集客力 `attraction` を使い、**その日の開店後の確定状態**から選択する。単純な「直近の施策IDから1枚選ぶ」方式は廃止する。
3. 苦情が **3以上のカテゴリが2種類以上**なら上位2カテゴリの組合せ画像を選択する。**最多カテゴリが4以上なら severe**、両カテゴリが3なら moderate。severeは「主問題が深刻」であり、二次問題まで必ず最悪という意味ではない。3つ以上のカテゴリが悪い場合、主画像に表れないカテゴリは下の数値・アイコンで残す。
4. 苦情が3以上のカテゴリが1種類なら単一問題画像を使用。該当が4～5なら severe、3なら moderate。大きな問題がない場合でも最も優先度の高い苦情に応じて mild とするか、基本状態に戻す（閾値はUIテストで決める）。
5. 課題が目立たない場合は、集客力が高ければ orderly/busy、低ければ underused、標準なら neutral を選択。**売上上昇だけで「改装済み」など存在しない設備は表示しない。**
6. register-added / aisle-rearranged / restocked / renovated は、該当する設備改善を実際に実行した場合のみ表示対象にする。ただし深刻な複合問題の写真を無条件に上書きしない。複数効果が重なるケースで未対応の見かけを作らないよう判定を監査する。
7. 同じ確定状態なら原則同じ写真。乱数で別の写真へ飛ばさない。**前日と数値が同じなのに景色が変わる**のを避ける。
8. 下の苦情4軸・集客力・施策効果の**数値アイコンは存続**。メイン写真と重複する小さな「別角度の状態写真」は削減候補とする。「何が変わったか」は翌朝の短い1文で説明。写真にタイトル文字を大量に重ねない。

## 試作ゲート（制作前監査で順序を変更）

**Gate P1：ユーザーの承認前は3枚のみ。**

1. `main-base-neutral.webp` — カメラ・店内レイアウトを確定するマスター。
2. `main-checkout-mild.webp` — 実際のプレイで頻出する「少し長いレジ待ち」。薄い差でも390px幅で分かるか。
3. `main-checkout-aisle-severe.webp` — レジ混雑が主通路へ波及する複合的で大きな変化。

**Gate P2：P1が合格した場合、Work内で追加3状態を制作・独立検品する。**

4. `main-checkout-moderate.webp` — mild と severe の中間の自然な強さを確認する。
5. `main-improved-register-added.webp` — 「有人レジを増設」後の設備が、後日の通常写真へ戻って消えてしまわないよう合成・継続表示できるか検証する。
6. `main-noise-severe.webp` — 音量を写真だけで十分に表せるか。無理に演技・動作を誇張して不自然にならないか検証する。

**Gate P3：P1/P2の不一致を解消したあと、残り28点を制作する。** ただし使用頻度・費用対効果が低い写真は、その時点で制作を取りやめ、必要数を下方修正してよい。総数を34に合わせるためだけの画像生成は禁止。

## 制作前の独立監査（2026-10-27）

### 1. 34枚すべてを最初から作るのは非効率

450周の機械模擬プレイ（施策選択に乱数を含む簡易テスト）で、記録できた2,655営業日のうち代表画像への分類は次の通り。人間プレイヤーの実際の分布ではなく、**優先制作する状態を考えるための参考値**。

| 店舗状態 | 簡易模擬プレイでの構成比 |
|---|---:|
| レジ・軽度 | 34.4% |
| 通路・中程度 | 9.5% |
| レジ・中程度 | 9.0% |
| 通路・軽度 | 6.4% |
| レジ＋通路・中程度 | 4.9% |
| レジ・深刻 | 4.7% |
| 初期仕様の `main-base-neutral` | 0.2% |

従来試作の3枚（通常・レジ深刻・レジ＋通路深刻）は、**出現頻度の高い「軽度・中程度」画像を検証できていなかった**。上記のP1/P2で是正する。

### 2. 34枚では全状態を忠実に表現できない

34枚は全景の「代表的な状況」を示す素材群であり、14,256通りの全状態を一対一に描写するものではない。主画像の優先度は一番深刻な問題、数値アイコンは4軸の全問題を担当する。静止画で表しにくい騒音は、実際の音量数値・アイコンを主情報とし、写真は売場の雰囲気の補助に留める。

### 3. レジ増設や改装と固定カメラの競合

**重大なリスク：** 単独の「増設済み」写真を見せた後、次の日に旧3レジの写真へ戻ると、増設した設備が消えたように見える。

Work側では、初回のマスターからの**部分編集・同一構図差分**を原則とする。「毎回ゼロから独立生成」は禁止。P2では増設の前後を実写感のある固定カメラで比較し、①固定位置の透明差分レイヤーを重ねて設備履歴を保てるか、②不可能なら増設状況を翌朝の結果画面と補助写真で示し、通常全景には矛盾する器具の数を写さないか、どちらかを実証すること。**解決しないまま残り28枚へ進まない。** Chat側は画像組込み時、施策履歴を使った矛盾回避処理を実装する。

### 4. 必須の視覚検品方法

- 最初に現行素材を参照して**1枚の撮影マスター**を制作し、それに対する局所編集で差分を派生させる。参照だけ与えて別画像を毎回独立生成しない。
- マスターと候補画像を50%透過で重ねる比較、横並び比較、390px幅でのサムネ比較を作る。柱・床境界・レジ・棚・放送設備の位置をチェック。
- 初期3枚は原画と並べ、どこが変わり、どこが保持されたかを台帳へ記録。全6画像の検品で**装飾なしで区別できるか**を確認する。
- 許容できない構図ずれが発生したら**その差分だけ差し戻し**。全34画像を一括再生成する状態にしない。

### 5. 写真の用途を区別

通常営業時の大きな写真は基本4＋単一問題12＋複合問題12の最大28種。改善・結果の6枚は、**施策結果や週報などの場面写真にも使えるが、状態写真へ無条件に上書きしない。** 既存社・DAY 7・DAY 8は優先的に従来画像を保持する。

現在の `store_scene_v018.js` はファイル名決定ロジックの**先行実装**であり、設備履歴の合成、固定カメラの画像内容検証、完成素材の配信確認は未完成。これらを解消することが新画像のゲーム本体接続条件。
