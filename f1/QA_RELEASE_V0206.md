# F1 v0.20.6｜1つのクレームから発見する施策の密度調整

**作品**：F1『すべてのご意見に対応してください。』  
**画面版数**：v0.20.6（2026-10-28 13:50:29 JST）  
**公開URL**：https://tora3-mystery.github.io/short-ui-games/f1/  
**変更範囲**：`f1/` のみ（INDEX・他作品の変更なし）

## 1. 調査で判明した問題

v0.20.4までは、基本の14個のキーワード群が3〜4施策を一度に発見し、さらに1日1度、約75%の確率で同カテゴリの別施策が追加されていた。したがって1下線で最大5施策、さらに1件のご意見に別の下線がある場合、より多くの施策が追加される構造だった。文章の中身を読んで操作する価値が低下し、後半は「確認済み」に偏りやすかった。

## 2. 新仕様

- **1下線で1〜2施策まで。** キーワード対応を14群から23群に分割。レジ待ち、品切れ、通路、騒音の具体的な文面ごとに対応策を差別化。
- **1件のクレーム全体から最大3施策。** 2箇所の下線がある場合は、通常1箇所目が2施策、もう1箇所が1施策。プレイヤーが調査する順序で解禁数は変わらない。
- **追加の確率抽選を廃止。** 従来の`randomBonusDays`/`randomBonusIds`は過去のセーブ互換性のため保持するが、新しく抽選して施策を追加しない。
- **分類だけに基づく汎用フォールバックも縮小。** 通常の下線に一致しない文面は、文面の決定論的ハッシュに応じた適切な2施策のみに対応。汎用文面の下線は1箇所。
- **施策の到達性を維持。** 50施策のうち46施策への下線導線を維持し、`audit`、`camera0`、`open0`、`removeShrine`の4施策は特殊条件で開く。
- 施策自体の売上・不満度・確率・分岐値は変更しない。初日の文面抽選、DAY2以降の38クレーム文面、後半の投稿数も維持。
- すでにプレイヤーが発見した施策を既存セーブから取り消すことはしない。新たに調査する下線に新上限を適用する。

**例**

| クレームの下線 | 今回解禁される施策 |
|---|---|
| レジに20分並びました | 有人レジ増設・予約受取窓口（2） |
| レジが長蛇の列 | 応援スタッフ手配・混雑時間の応援固定（2） |
| レジに20分並び、カートも通れなかった | 2下線を全部調べても合計最大3 |
| 見掛けない商品がありました | 棚の商品と仕入伝票の照合（1） |
