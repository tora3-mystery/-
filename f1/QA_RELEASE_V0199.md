# F1 v0.19.9｜DAY 8既存セーブ復元の修正・再発監査

**作品：** F1『すべてのご意見に対応してください。』  
**画面表示：** F1 v0.19.9／2026-10-28 12:48:30 JST更新  
**対象：** `f1/` のみ。ルートINDEX、他作品は変更しない。

## 1. 調査結果

v0.19.8の既存実装では、DAY 7営業報告から `advance()` が呼ばれると、未完了の施策ジョブをDAY 8で確定させ、`odd>=3` なら `beginDay8()` → `day8Active=true` → 開店準備 → 人曜日の営業画面へ進む。通常の7日間終了ではDAY 8へ進まない。

しかし、**過去のセーブ・不整合データ**で `day===8` かつ `day8Active===false`、`finish===false` となった場合、従来の `load()` と `resumeCurrent()` は復元しなかった。特に `odd>=3` であっても `render()` に流れ、`DAY 08 / 07 ｜ 人曜日` の通常指標・通常施策画面が表示される。これは「DAY 8まで来たのに不穏な演出がない」という報告と症状が一致する。

※過去の端末の実セーブを取得していないため、当時の不具合の根本原因と断定していない。v0.19.7で意図的に増強した人曜日演出もv0.19.6当時とは区別する。

## 2. 修正

- `recoverDay8Save()` を追加。未完了のDAY 8で専用画面のフラグが欠落している場合に補正する。
- `odd>=3` の場合は `day8Active=true`、人曜日UIへ復元。最後のご意見を未調査なら開店準備を再度表示し、すでに調査済みなら選択を保持する。
- `odd<3` の場合は存在しない通常営業8日目を表示せず、通常の7日間の週報へ復帰。
- 復元時は古い `needsAdvance` と `undoSnapshot` を破棄し、状態を再保存。再度のリロードで不整合を再発させない。
- `load()`・`resumeCurrent()`・`render()` の入口で保護。通常のDAY 1〜7や正規のDAY 8状態には変更を加えない。
