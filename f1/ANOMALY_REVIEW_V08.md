# F1「改善しすぎる店」v0.8｜不穏ルート設計・仮想5視点レビュー

判定基準：2026-10-25 JST  
ステータス：作業ブランチ試験実装／未承認・未公開。画像未配置。5視点は**AIの役割別検討であり、人間5名の試遊ではない**。

## 1. 共通して守る作品体験
- 通常のスーパー経営と、経営システムの異常を同じ7営業日のルールで進める。
- ホラー導入は任意。通常施策だけでも通常N1/N2/N3に到達できる。
- 怪しい選択肢は赤枠・「不穏」のラベル・露骨な0番レジ名を使わず、普段の業務改善として見せる。
- 改善の副作用で生じる通常クレームを怪異が消してしまわない。
- 0番レジが「帰らない客」と終わったはずの営業日を取引として計上する、という一貫した怪異の核を持たせる。
- 初回10分以内を優先し、第8営業日は短い特別画面のみとする。

## 2. 5つの専門視点による検討
| 立場 | 評価・対立論点 | 採用した対応 | 未解決 |

## 3. 導入・進展の正本（仮決定）
1. **異常度0**：通常のスーパー経営。既存4不満指標、開始資金120万円、日次6施策。
2. **入口：未処理売上の自動照合**：2日目以降、手元資金が120万円を下回る／深刻な苦情がある／4日目以降などの条件を満たすと候補。必ず選ばなければならないわけではない。費用0、短期増収という誘惑。
3. **異常度1**：一件の売上計上日付が翌営業日になっている。閉店後売上や未退店数という異常指標が見え始めるが、レジ0の正体は確定させない。照合票Aを調査できる。
4. **異常度2：来店動線データを販促へ活用**：先日付のカメラ映像と売上予測がつながり、客が見えないのに取引人数が増える。照合票Bを調査できる。
5. **異常度3：未使用レジの試験運用**：端末が番号0を表示し、閉店操作を拒否。照合票Cを調査できる。
6. **7日目の閉店選択**：停止(X1)、営業継続(異常度3ならDAY8へ／その他はX2)、残留客の確認（照合・推理によってX4またはX2）。
7. **第8営業日**：DAY 08/07を実際の画面として表示。閉店申請を繰り返すとX3。説明できない売上を確定するとX2。固定画像はodd3再利用、X2とX3の結末画像は別途予定。8日目は一般の6施策メニューを繰り返さない。

## 4. 証拠と最終推理
- 照合票A：売上計上日＝明日、返品対象＝1営業日前。
- 照合票B：入店者0人、明日の店長代理と同じ社員証の人物が閉店後の映像に写る。
- 照合票C：返品希望者の社員番号と自分の番号が一致し、出勤日1日分の返還希望がある。
- **アンロックと確認の区別**：怪異施策実行は証拠を閲覧可能にするが、閲覧しただけでないと最終推理が有効にならない。UI上で照合票を開いた履歴は端末保存する。
- 推理は「最後の客＝未来の自分」「返品品＝昨日」の二項目。1回目の誤答後は再照合可能、2回目の誤答はX2。初回の推理ミスだけで即終了しない。
- X4の説明は、終わったはずの営業日が未処理の昨日として重複計上されていた、という因果に結び付ける。

## 5. 7エンドの対応
| ID | 名称 | 実装候補の結果 |
|---|---|---|
| normal_success | N1 優良店舗 | 最終資金120万円以上／全不満度3以下 |
| normal_customer | N2 黒字の不便な店 | 最終資金120万円以上／不満度4以上あり |
| normal_strain | N3 改善しすぎた店 | 最終資金120万円未満 |
| odd_stop | X1 0番レジ封鎖 | 異常利益相当額を手放し、閉店 |
| odd_missing | X2 お客様のいない繁盛店 | 誤った/不足した推理、または第8営業日で異常売上を確定 |
| odd_day8 | X3 閉店できない店 | 異常度3で継続→DAY08/07で再度閉店申請、承認されない |
| odd_hidden | X4 最後のお客様 | 3証拠を閲覧して2項目の正しい推理を完成 |

**注意：** X1とX4は現時点で同じように異常指標を0へ戻す一方、現金残高の処理が異なる。これはシナリオ・会計両面の重要な未決論点であり、正式版で意図的な差として説明するか統一するか判断が必要。最新版のロジックはまだ凍結していない。
