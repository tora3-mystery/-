# S6 β｜人物性格DB・会話エンジン v0.3.0

更新基準：2026年10月27日。対象 `s6/beta/` 限定。
S6現行公開版 `s6/game-data.js`、画像 `s6/assets/faces/`、ルートindexは改変しない。

## 目的と分離

S6の主たる遊びは**大量の顔・名前・所属・人間関係を覚え、SNS等で照合して安全なサークルを選ぶ**こと。
台詞を大量に追加してADV化するのではなく、同じ人物が初回／再会／交流後に一貫した反応を返すため、データとロジックを分ける。

| 層 | 入力元 | 役割 |
|---|---|---|
| 人物の正史 | `../game-data.js` | ID、名前、学年、所属、掛け持ち、担当パート、顔画像、紹介台詞、質問、SNSアカウント |
| β人格DB | `character-profiles.js` | 96人のinitiative/warmth/caution/expressiveness、voice、snsTone、role、interest |
| 場面の記述 | `../game-data.js`のevents/groups/lines | 団体・イベント・輪の会話。雰囲気・伏線などの固定部分は手書きのまま |
| 話し方と反応 | `dialogue-engine.js` | 人格＋学年・イベント＋関係の距離＋既存の人物フックから返答文を構築 |
| プレイヤー状態 | `game.js` | 初回紹介済、話しかけた回数、affinity、連絡先、知っている所属、人物照合状態、CASE Aの証拠 |

## 人格DB

96人すべてを明示IDで保持。性格値は0〜4（高いほど強い傾向）：

- `initiative`：相手に話しかける積極性
- `warmth`：親しみを表に出す度合い
- `caution`：初対面やSNSでの警戒心
- `expressiveness`：感情・抑揚の豊かさ
- `voice`：friendly / energetic / casual / quiet / soft / precise / reserved。固定の発話の癖を表す
- `snsTone`：active / quiet / private / curated。SNSの文章や公開傾向を監査する際の人物ごとの指針
- `role`：newcomer / member / senior（学年設定から）と、各イベントでの host / guest（掛け持ちも考慮）は区別
- `interest`：担当楽器を人物の興味として参照。元DBの職掌と独立した設定を捏造しない

**暫定値：** P001〜P016とP091〜P096は個別調整済み（あくまでβ仮説）。その他は既存`social_style`、学年等を出発点に異なる設定値を割り当て、ファイルに固定した。性別・顔立ち・国籍から性格を推定しない。完成時には個別人物の人物像に合わせて人間が調整する余地を残す。

## 会話生成の優先順位

1. **真相・証拠の整合**：CASE Aの重要人物・伏線は勝手にランダマイズしない
2. **どのイベント・団体か**：その会場の主催者／掛け持ち参加者／新入生を区別
3. **関係の距離**：初対面→知り合い→親しい相手／連絡先交換済み（`affinity`と連絡先を使用）
4. **人物の口調**：同じ人物は別の場所でも同じ基調
5. **人物固有の音楽の話**：`socialProfiles.first_hook`・`reunion_hook`を再利用
6. **当該グループの質問**：`questions`の既存88個の答えを尊重
7. **SNS**：`accounts.avatar_kind`と投稿公開範囲を維持。SNS文体・ハンドルの全面改訂は後続作業

異なる人物に同じ汎用台詞を無条件に割り当てない一方、すべての反応を人工的に違わせない。

## 口調・台詞上の禁止事項

- 発言バブルの中に「『…』と声をかけてくれた。『…』」のような**ナレーションと本人発言の二重引用**を入れない
- グループの自己紹介を終えたあと、普通に話しかけただけでフルネームを再表示しない（自力照合のゲーム性を守る）
- 初回自己紹介の直後に、同じ自己紹介をもう一度繰り返さない
- 新入生が会場主催者のように安全案内・受付運営を取り仕切らない
- 質問で自発的に名前を聞いたときは、会話として明示的に教わる扱いと区別する
- 過剰な語尾変換やキャラ付けをせず、普通の大学生の日本語を優先する
- 台詞に書かれた情報が手帳・所属・SNSの参照状態に反映されること

## 旧台詞の個別修正

元データ132行のうち、**新入生が発言する10行をβ版で差し替え**。例えば、新入生が他人の顔出し公開範囲を指導するような台詞を、本人の戸惑いや質問に変更した。

適用元は`character-profiles.js`の`sceneOverrides`。共通DB `game-data.js`の原文は残す。

## β v0.3.1｜「好感度」ではなく、日常的な話しやすさ

- `S.affinity[id]` は本人の魅力・主人公への好意を示す値ではなく、実際に交わした対話によって蓄積される関係履歴（0〜6）。話す／質問するで+1、1人物1日2点まで。
- `S.relationshipDays[id]` は意味のある会話があった日付の集合。閾値は次のとおり。

| 段階 | 内部条件 | 手帳の表記 |
|---|---|---|
| new | 0 | まだ話したことがない |
| acquainted | 1以上 | 話したことがある |
| familiar | 3以上かつ別日2日以上 | 少し話しやすくなった |
| easygoing | 5以上かつ別日3日以上 | 気軽に話せる |

- TINE交換は別の状態 `contacts` に保持し、交換そのものでは関係レベルが上がらない。恋愛・独占・特別な告白・親密度ランキングは追加しない。
- 日付の異なる再会でセリフが変化する。人の固定口調は変わらない。プロフィールに本名が出る条件と、対面での知り合い度合いを混同しない。
- `snsMessage` はTINE交換済みの人物に限り、設定済みの `snsTone`（active/quiet/private/curated）とこれまでの会話距離で短文を構築。公開SNS投稿そのものの全235件の人物別監修は別工程。
- 既存の `S.guesses`（顔・名前・所属の照合）、`S.socialLinked`（SNS写真の照合）、`S.affinity`（対話の経験）、`S.contacts`（連絡先交換）は別々の情報として持つ。**親しさの高さを安全判定や推理の正誤判定に使用しない。**
- 新しい自動試験5件を追加し、既存と合わせて29/29 PASS（コード＋仮DOM）。実ブラウザと人間試遊は未実施。

## β v0.4.0｜人格感応度とSNS人物像

### 感応度

- 既存`affinity`は恋愛好感度ではなく会話を重ねた経験値。性格が固定され、交流に反応する速さだけが人物によって異なる。
- `Dialogue.responseGain(person_id, action)`は`warmth + initiative - caution`を基準に、`action`がtalkかquestion/affiliationか、慎重さ・表現傾向を加味し、0.5 / 0.75 / 1.0 / 1.25点を返す。
- 初対面での気軽な会話に反応しやすい人物と、慎重だが丁寧な質問には話してくれる人物とで感応度が変化する。上限1人物1日2点・累計6点は不変。
- 親しさの段階には別日遭遇の条件を残す。連絡先交換のみで加点しない。SNSの顔照合が正しくても親しさ加点しない。**親しい＝危険でない**とは決してみなさない。
- 既存セーブの整数affinityは数値として読み込み、今回の小数加点と共存する。別日の架空の交流履歴は補完しない。

### SNSの人物表現

- `social-personas.js`に235件のアカウント定義のβ用表示名・ハンドルを明示保存。`snsTone`を単なる表示文言に使うのではなく、対面人格と対応した傾向として扱う。TINEは実名・愛称寄り、Photogramは趣味・日常、Zitterは匿名・趣味名・愛称を混在させる。
- 固有アカウントのハンドルは人物IDの`tine_001`等ではない。名称とハンドルの完全一致を強制せず、**同じ人物だと気づける場合も気づけない場合もある**ようにする。
- 運用上の重要制約：`visibility`、`avatar_kind`、SNSの投稿者ID、投稿日時、CASE Aを支える既存の投稿内容の意味は元DBと一致。**匿名表示投稿には作成者の表示名・ハンドル・写真を決して表示しない。**
- `postTexts`24件はβ限定の文章表現差分。ストーリー上の時刻・出来事の改変は行わず、各自の性格に沿う口調に置き換えた。
- TINEに未交換相手の私信を表示しない。交換後メッセージは連絡状況と個性で変わるが、いずれも本名照合や犯人特定の自動成功には使わない。

### 自動検査

`node s6/beta/test-beta.cjs`：36件すべてPASS。96人の会話感応度、235SNSアカウントの一意性と原DBの可視性・アバター条件の保全、匿名投稿の秘匿、鍵投稿の閲覧権限、24投稿の参照整合を含む。DOM模擬試験であって、実ブラウザ・人間の自然さ評価ではない。

## β v0.5.0｜会話の場面適合・先輩後輩・周辺の反応

- `sceneLine`は同一人物が同じ輪で複数回発言するため、優先キーを`group_id|person_id|line.order`→`group_id|person_id`→元DB文章の順に変更。
- 年次の境界：1年生は新歓に参加する新人、2年生以上は既に所属しているメンバー。先輩を相手にした新入生の台詞は丁寧な口調に改稿。E01-D、E06-Eなど先輩の入会不安や再見学の不自然な説明は訂正。
- `sceneMode(group_id)`は演奏・リハ・セッションの輪を区別。公演途中に立ち話をさせず、短い休止時間としてUIに表示する。イベントと一致しない固定フックの部分補正も行う。
- `thirdParty(targetId,groupId,state,action)`は同じ輪の第三者が短い反応を返す。話者の学年／相手の学年に合わせ敬語を選ぶ。追加の行動回数や親しさ点は発生せず、名前を自動開示しない。
- セッション毎の`presentationSeed`は並び順・雰囲気のみ変え、DB上の人物・所属・会話・証拠は変えない。
- TINEとPhotogramは独立した同意・承認状態（`contacts`対`photoRequests/photoFollows`）。Photogramは対面で本人に尋ねてフォロー申請→翌日承認。TINEでの関係の深さとは無関係。
- 43件の回帰試験と180件の状態遷移模擬は全通過。リアリティ・文章の自然さは人間初見レビューで追加判断する。
