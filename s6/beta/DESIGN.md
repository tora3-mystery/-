# S6 β版・原点回帰仕様（v0.5.0）

- 人物DBの`initiative / warmth / caution / expressiveness`から、`Dialogue.responseGain(id,action)`が交流ごとの親しさの増加量を算出する。話す・質問・所属確認の種類でも感応度は異なり、**0.5〜1.25**の範囲。連絡先交換・SNS閲覧・人物照合で自動上昇しない。
- 同一人物の1日あたり上昇上限は従来どおり**2点**。高い関係段階には別日に出会う必要があり、性格が社交的という理由だけで短時間に親友にならない。
- 性格の感応度は「内面的な安全度」を示さない。CASE Aの安全ルート・犯人特定・事件の証拠・結末分岐には利用しない。
- β専用 `social-personas.js` を新設。共有DBの235アカウントに対応する、**235件全ての表示名とハンドル**を明示保持（TINE 96、Photogram 73、Zitter 66）。外部表示のハンドルは人物ID直結の仮名称を廃止し、性格の`snsTone`・音楽の興味・プラットフォームを使い分けた。匿名アカウントでは表示名・ハンドル・顔写真を画面に出さない。
- SNSの公開状態・顔出し`avatar_kind`・人物ID・投稿者・日時・投稿の可視性条件は**元DBと同じ**。顔写真素材や本編`s6/`の共有JSは変更しない。TINE連絡先表示と連絡先交換時の表示名もβ専用の値を使う。
- β専用の投稿文面`postTexts`24件を人物の口調に合わせて調整。イベント曜日、団体の情報、匿名性、CASE Aの伏線に関わる事実は変更しない。
- SNSアカウント名235件と投稿24件は**第一稿**。固有人物設定との整合・実際の大学生らしいネーミングは人間試遊および専用の文面監査で改善する。画像Work側のSNS用アイコン素材制作とは別工程。
- βの`index.html`は `game-data.js → character-profiles.js → social-personas.js → dialogue-engine.js → game.js` の順で読み込む。
- 自動状態遷移QA：`node s6/beta/test-beta.cjs` **36/36 PASS**（姓・匿名表示、鍵投稿、公開SNS名、人物ごとの感応度、再会、旧セーブ、CASE Aの危険ルートなど）。**実ブラウザ・人間試遊は未実施**。

## β v0.4.1｜独立監査・SNSの照合判定漏れ修正

検査内容：2026-10-27。元の`s6/`本体・人物DB・画像・INDEXは変更しない。

### 修正したゲーム性上の不具合

- 旧実装では、SNS投稿の本人にまだ会っていないと**顔を見比べるボタンが消えた**。これが「そのSNSアカウントの本人に会ったかどうか」を教える隠れた正解表示になっていた。
- さらにSNS側の顔を選んだとき、合っているかどうかを直ちに表示するため、総当たりによる特定が可能だった。
- **新仕様：** 公開された顔写真は、手帳に顔が1人でもあれば誰の投稿でも見比べられる。選んだ顔はプレイヤーの`socialCandidates[post_id]`に**推測として記録**するだけ。正誤は表示しない。再選択・修正でき、前候補のSNSメモも削除される。手帳には「自分のSNS照合メモ」と表示し、確定事実とは区別する。
- SNSの閲覧権限を直接ボタン操作で迂回できないよう、照合ハンドラでも投稿日・可視性・顔出しを再検査。
- 旧βの`socialLinked`を持つ保存は読み込み維持し、新規の`socialCandidates`がなければ空のオブジェクトとして補完する。

### 検査結果と境界

- 自動回帰テスト：**38/38 PASS**。SNSの隠れた人物ID判定を利用する旧操作を封じ、匿名・鍵投稿・未来の投稿の保護と元の一週間の分岐を確認。
- 追加で、複数イベントの選択・最大2輪の行動・夜の手帳・SNS/掲示閲覧・セーブ復元・6団体/辞退・危険/救助/辞退を組み合わせた**240ケースの決定論的状態遷移模擬テスト**を実施。エラー0。結末到達数：SAFE 206、RESCUED 17、DECLINED 11、DANGER 6。
- これはDOM模擬によるロジック検査。**実ブラウザ・実スマホ操作と人間の初見プレイは別工程**。

### 次の人間レビュー待ち・未変更事項

1. 人物手帳の無制限照合は、プレイヤーが名前と所属を総当たりする余地を残す。ユーザー指定の「夜のみ・無制限」は維持し、難易度・やりがいは人間テストを待つ。
2. Photogramの鍵垢投稿は、現行βでTINE連絡先交換済みなら閲覧可能という簡略化になっている。今後、フォロー承認を別管理するかをUXレビューと合わせて判断。今回、仕様変更しない。
3. 主筋CASE Aの伏線、合宿選択の難易度、交流回数や親しさの数値は、ユーザーの人間試遊結果を受けて判断。監査だけを理由に変更しない。

## β v0.5.0｜大学生としての口調・会場ごとのリアリティ・新歓の周回差分

実施：2026-10-27。変更範囲は`s6/beta/`のみ。元の96人DB、44グループ、12イベント、全証拠・CASE Aと週末分岐は維持。

1. **学年と会話：** 元DBのグループ台詞132行と役割・年次・イベントを突き合わせ、初年度の人物は先輩に敬語・丁寧語で話すよう修正。`E01-D`では3年生・2年生が入会を心配していた矛盾を、「新入生からの質問にどう答えるか」へ変更。`E06-E`でも先輩が自分の再見学を願うような台詞を変更。複数行を話す同一人物は`group_id|person_id|order`で差分を個別管理し、1行目と3行目を誤って同じ文章にしない。
2. **イベントの実際：** 演奏・リハーサル・セッション系19グループでは、**演奏が切れたところで会話が始まる**説明を追加。受付用の台詞を別会場へ流用しない（例：E06の神谷杏奈）。演奏中の長い会話を表現しない。もともとの演奏・ライブ・公開範囲・撮影同意などのグループ事実は維持。
3. **輪の反応：** Aに話す／質問／連絡先／Photogramについて聞くと、実際に同じ輪にいるBが短く反応する。Bの学年とAの学年、演奏グループか否かで口調を分け、先輩へのタメ口を避ける。この反応は**自分の行動回数に数えない**。既存台詞や証拠条件も変更しない。
4. **周回時の見た目：** `presentationSeed`をセーブに保持し、日付ごとのイベントカード順、輪カード順、その輪の顔写真の並び、雰囲気を示す短い地の文だけを周回ごとに変化。人物がどの輪に所属するか・誰が発言したか・質問・証拠・写真・イベント日時は変更しない。新顔の水増しもしない。
5. **Photogram鍵垢：** `TINE`連絡先交換と独立。対面での輪内行動に「Photogramを聞く」を追加。鍵垢の本人に申請すると`photoRequests`へ入り、**翌日**`photoFollows`へ移る。フォロー済みのみ鍵投稿閲覧可。TINE交換だけでは鍵投稿不可。公開プロフィール閲覧・匿名表示の保護も従来どおり。
6. **手帳：** ユーザーが許容した夜の照合無制限はそのまま保持。照合の結果からSNSアカウントの正解を教えるUIはv0.4.1で修正済み。
