# B1｜初見プレイヤー代理プレイ監査・再レビュー（α0.1.2）

更新日：2026-10-26 JST。対象：`b1/index.html`。実際の被験者を募集した「人間のユーザーテスト」ではなく、AIが初見プレイヤーの行動を再現した模擬プレイとコード上の操作検証。

## 監査目的
採用判断が主役になっているか、初見でゲームルールが分かるか、面接で情報を得る意味があるか、条件付き承諾に整合があるか、採用失敗時に原因が納得できるかを確認。

## 模擬プレイヤーの行動
| 行動像 | 面接・採用 | α0.1.0の結果 |
| --- | --- | --- |
| 慎重な採用担当 | 8人全員に「曜日」「採用条件」を質問、佐藤・高橋・加藤・伊藤を採用 | 13/13、成功 |
| 技能重視 | 高橋・中村・吉田・伊藤 | 12/13、失敗 |
| 直感派 | 履歴書のみで田中・高橋・佐藤・伊藤 | 12/13、失敗 |

| 人数バランス重視 | 佐藤・高橋・山本・伊藤 | 12/13、失敗 |

先頭ケースのUI模擬操作は36クリック。実時間計測・実際の人間の理解度検証は未実施。

## 検出事項・対応
### 修正済み
1. **条件未達でも無条件に承諾していた（高）**：本人必須条件に違反するオファーでは理由付き辞退とし、了承した場合は「条件付き承諾」と明示。配置探索では必須条件の優先度を人数充足より高くした。
2. **8人全員を見ずにオファーできる（中）**：応募者の全プロフィールを一度確認するまで正式オファーを送信できないよう変更。質問は必須にしない。
3. **失敗時に原因を説明しきれない（中）**：不足した曜日・時間帯を表示。固定ケースの既知の成功組合せから、代替採用案を説明。ただしこれは採用し直した場合の反実仮想として表示し、確定採用の撤回はできない。
4. **既存スタッフの助言が候補に連動しない（中）**：小林は現在の確認済み条件で不足する枠を指摘。村上は初回研修の注意を表示。
5. **振り返り計算が重い（中）**：結果画面で全70組の再探索を毎回行う処理をやめ、固定ケースについて監査済み成功9組を利用する。代表ケースの結果表示処理は4〜11ms（特定のJavaScriptテスト環境での測定）。

### 今後の企画・UX課題
- 2質問の最適解が「勤務曜日」「採用条件」に偏る。技能、人間性、本人希望の質問にもゲーム上の情報価値を付ける設計が必要。質問回数を増やすだけの修正はしない。
- 応募者の会話が事務的で、人物関係の存在感が弱い。自然な追加発言、面接官の掘り下げ、オファー返答の個性を強化したい。
- 顔画像は仮イラスト。人物の区別や記憶を支える画像・肩書き・特徴などの設計が必要。
- 現状は勤務条件固定。ランダム生成ケースの解保証と周回難易度制御は未実装。
- 初回プレイ時間10〜15分は未実測。36クリックを要した模擬操作は参考であって、人間プレイ時間ではない。

## α0.1.2の回帰テスト
- 4人採用組合せ **全70組**：成功成立条件を満たすもの **9組**。
- 全70組について「8人を確認→4人にオファー→営業結果」を模擬実行。**20組で1人以上の辞退**、**9組は13/13達成**。4人承諾したにもかかわらず必須採用条件が未達となるケース **0件**。
- 人数が足りない具体例（高橋・中村・吉田・伊藤）：不足枠と採用代替案の表示を確認。
- 条件交渉例（田中・高橋・中村・吉田）：田中辞退を確認。
- 8人未面接でのオファー送信ブロック／全員面接済みでの送信許可を確認。
- 新バージョンのJavaScript構文検査を通過。

## 監査の限界
- DOM画面文字列・イベント処理を模擬するJSテスト。**Chromiumの実画面、スクリーンショット、実機スマホ操作、人間によるユーザーテストは未実施**。
- GitHub Pagesはこの監査環境から直接開けなかったため、実公開URLの表示完了を断定しない。
- 公開済みとの報告はGitHubリポジトリのコミット反映とは区別すること。

## 5視点最終レビュー
- 佐伯（企画）：良いのは採用評価と店舗適性の乖離。質問の価値の多様化を最優先。
- 三浦（ゲーム）：9/70の固定ケースで選抜の難しさは成立。ただし無制限の試行による攻略を想定し、隠し情報と助言のバランスを調整。
- 黒田（シナリオ）：条件違反の辞退理由は自然になった。人物固有の会話・エピソードを追加。
- 篠原（UX）：候補ボードから採用通知への導線は明確化。スマホの実寸・操作テストは必須。
- 大塚（QA）：条件付き承諾の整合性を強化し全70通り再検査済み。今後の本格ランダム生成はケースごとの解探索を必須とする。
