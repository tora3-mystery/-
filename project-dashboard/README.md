# 短編UIゲーム実験室｜内部進捗・監査ダッシュボード

## 入口

- 表示: https://tora3-mystery.github.io/short-ui-games/project-dashboard/
- 状態データ: `projects.json`
- 画面: `index.html`
- 管理: ARG企画マスター
- **非リンク＝非公開ではない**。このリポジトリとGitHub Pagesは公開。個人情報、未公開シナリオの真相、社外秘などは記録しない。

## 記録の原則

1. **工程進捗** は0〜8の現在フェーズ位置。工程の割合であり品質や制作残時間を表さない。
2. **AIロジックQA、実ブラウザQA、人間レビュー** は必ず別欄で記録。模擬DOMの結果を実ブラウザ試験完了とみなさない。
3. **人間レビュー** は対象バージョン、実施日、指摘/承認が明確な場合だけ「最新版確認済み」と記録する。対象バージョン不明なら「旧版（版数未特定）」にする。
4. **画像Work** は「制作中」「GitHub素材保存済」「ゲーム組込済」を区別する。
5. GitHubの最新ファイルとコミットを取得した上で版数・状態を更新する。確認できないものを推定で「完了」にしない。
6. 原則、作品専用Chatは自身の作品フォルダだけ編集し、**`project-dashboard/` は企画マスターが管理する**。専用Chatは更新報告をマスターに渡す。
7. 作品専用Chatからの進捗報告、GitHubからの技術データ、人間によるプレイ結果を分けて記録する。

## 毎回の更新フロー

- 各作品で大きな更新、Work素材保存、人間レビュー、Gate判定があれば、専用Chatが次の形式で企画マスターに報告する。
- 企画マスターはGitHub上の実装/QA記録を確認し、`projects.json` の該当行を更新する。
- `sourceFile` と `sourceSha` に、確認した代表ファイルの**Git blob SHA**を記録。新しいコミットにより変更されたら、Web表示時に差分確認を促す。
- ダッシュボードは`projects.json`をページ読込時に取得するため、そのファイルの変更は再読込により反映する。
- ブラウザのGitHub差分チェックは**監視対象の代表ファイルのみ**であり、他のJSや画像だけの変更や、人間レビューの実施を完全には検出しない。
- 常時実行・自律的な全Chatの情報集約はこの静的ダッシュボードでは行わない。定期巡回は別途スケジュールタスク/運用ルールが必要。

## 更新報告テンプレート

```text
ID／作品正式名：
コード最新版／JST更新日時：
GitHubコミット：
現在フェーズ（0〜8）／公開区分：
AIロジック監査：内容・対象版・結果・未検証範囲
実ブラウザ監査：内容・対象版・結果・未実施なら未実施
人間レビュー：実施日・対象版・指摘・検証済みか
素材：未着手／Work制作中／素材保存済／実装済
重大な残課題：
次の担当（Chat／Work／人間）と作業：
```

## 機能

- 14案件（INDEX掲載12 + K1マンション + D3鉄道版）
- ID/タイトル検索、進捗順・Work候補ソート、レビュー・Work稼働状況のフィルタ
- Phase 0〜8のゲージ（**工程位置**）
- 人間レビュー対象版と最新版の相違の明示
- GitHub APIの**1回のtree取得**による、14個の代表ファイルの変更検知（静的JSON自体の自動修正はしない）
- 各作品のプレイURL・コードへのリンク

## 運用上の未整備

- 各専用Chatからマスターへの更新報告の完全自動化
- 最新版の実ブラウザ・人間レビューの監査証跡
- 代表ファイル以外の変更の自動検出
- 非公開の閲覧制限（必要ならprivateリポジトリや権限制御付きサービスに移行）

現時点では正式な機械的監視ではなく、**マスターのレビュー台帳と軽量な鮮度チェック**である。
