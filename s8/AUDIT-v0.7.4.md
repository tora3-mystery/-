# S8｜全件シナリオ・講義・文章監査 v0.7.4

監査日：2026-10-29（JST）
対象：`s8/` 内の現行ゲーム実装、学部別必修・選択講義、学習スキル、科目評価、進級・卒業表示、履修確認、成績発表。
責任範囲：本監査は通常Chatによるソース監査＋モックDOM/ロジック試験。ブラウザ実画面・実機操作・人間初見プレイを代替しない。

## 1. 件数・講義バリエーション

- 講義定義：**109件**（講義ID **105種類**）。英語Ⅰ・Ⅱが3学部に共用されるため、定義数とID数は異なる。
- そのうち必修：36定義・32固有ID。選択・上級選択・通年等：73定義。
- 成績評価方法：レポート32、試験32、課題22、ゼミ7、通年6、出席5、実験5。
- 難度（★1〜5）：3 / 18 / 29 / 39 / 20定義。
- 低年次の共通教養は前期・後期で異なるプール、学部固有の選択2科目ずつ、共通拡張24科目、専門ゼミ・卒業制作・通年科目が存在する。
- 結論：単純な講義種類数は不足していない。ただし学部固有の選択講義は少数で、共通科目が長く残る。特定の科目が未取得なら後年に繰り返し出る設計なので、周回時の変化は実際の履修結果に依存する。

- 新版は噂・ネットの声の2種類をそれぞれ別のハッシュビットで選ぶため、独立した組み合わせが出る設計。
- 取得率詳細の240件照合：最終表示値と主要内訳合算の差が2pp以内235件、最大絶対差8pp、10pp以上の差0。残差は別行で表示される。

## 4. 未解決論点（意図的に今回変更しない）

1. **履修前提の厳密さ。** 「微積分Ⅰ」を落単しても「微積分Ⅱ」が必修として割り当てられる場合がある。大学の厳密な先修制とは異なるが、後から必修の配置／進級条件へ影響するため今回の文章監査ではゲーム規則を変えない。
2. **選択科目の追加口コミ差分。** 73件の選択等定義には科目固有のrumor/netがあるが、多くは1案ずつ。共通科目が後年も出ると同じ文章が表示される。今後、優先科目に第2案を作成する。
3. **学部専用の選択講義比率。** 学部差は必修・ゼミでは明確だが、共通教養科目の母数が大きい。学部ごとの個性を強めるなら選択肢を増やす一方で、科目数だけ増やすことは目的にしない。
4. **取得率説明の完全な数式分解。** 主要要因は表示されるが、上限処理・端数・補正順の差を残差として表示する。現在の成績抽選には最終取得率が使われるが、完全な逐次再計算表ではない。
5. **旧基盤コード。** 初期v0.1系の表現（「1年次」「2学期試作」等）が基底関数中に残るが、現行後段スクリプトで表示を上書きしている。将来の大規模リファクタリングで整理が可能。今回削除するとデコレータ間の不整合を招くため変更しない。
6. **UIのメタ表現。** 「スキル」「単位取得見込」「スコア」「GAME OVER」は本作の明示的なゲームUIとして維持。講義本文・学生の噂・ネットの声には攻略ルートやシステム解説を入れない。

## 5. 人間レビュー優先事項

- 文学系／経済系／理工系を1プレイずつ行い、必修・選択の噂が学部に合うか。
- 新規・過年度の保存データで、必修の噂と再履修名が自然に表示されるか。
- 通年前期の全科目成功・失敗時に「単位確定」と誤認しないか。
- スキル加点を得た後の科目得点内訳が最終スコアと一致するか。
- 320px/390px相当のスマホ画面で長文による崩れや重要ボタンの押しづらさがないか。

## 6. 結論

**大きな数的バリエーション不足はないが、必修の文章が共通定型文に集中していたことが品質上の主要課題**だった。今回32固有IDに独立した2案ずつの噂・口コミを用意し、学部設定の誤り・表示上の旧仕様・得点説明の不整合を改めた。残る課題は、人間レビューと、プレイヤーに繰り返し出る選択科目の文章追加差分の優先順位付けである。
