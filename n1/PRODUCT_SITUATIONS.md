## 中核ルール

商品名だけの差し替えは禁止。商品カテゴリ・実際の価格帯・商品ごとの用途指定を用いて、出題文・導入・会話・採点の満点帯・リアクション・翌日や最終日の回収を一体で切り替える。

## ルールと個別補正

基本5タイプ：office_supplies / office_equipment / farewell_gift / spouse_gift / household_supplies。カテゴリと価格帯から自動分類するが、商品ごとの特有の用途を優先する場合はcatalog-v1.jsでsceneOverridesを指定できる。

sceneOverridesの例（架空データ）：

    sceneOverrides: { fujino: 'office_equipment', shoji: 'office_equipment' }

消耗品の具体的な使い方はsceneVariantで調整。現在はtraining_handout、device_care、breakroom_item、office_trial、event_tokenを使用。商品ID単位のsceneVariant指定も可能。未定義のタイプは実行時エラーとして出題を止める。

### 一貫性の条件

- 独立した4つの商品枠では重複しない。木曜と金曜の庄司の商品は完全一致、月曜と金曜の梅田の商品も同一ID・金額。
- 金曜の質問・会話・終了後の庄司の言葉は、前日に選んだ用途に対応する。事実価格と予算額・見た目の金額の違いを保つ。
- 消しゴムや社用車を唐突に妻・送別品として扱わない。値の違いだけでなく動機と人物の立場を整合させる。
- 会話にはspeechNameを使用し、商品カードには正式名称・型番を維持する。legacy商品の通称が正式名称になっていた場合は自然な呼び名へフォールバックする。
- 追加商品の公式価格が未確認、画像カテゴリ素材が未納品の場合は出題に使わない。

## 所掌分離

**Chat：** 商品の用途マッピング、登場人物のシナリオ、採点・反応・因果関係、商品DB、画像の本編への組込み、QA。

**Work：** 発注済みの共通カテゴリ画像32枚の生成・加工・素材台帳・GitHub保存。ゲーム本体・シナリオ・採点のファイルは変更しない。Workが商品ごとのシチュエーションを新規執筆する必要はない。
